What drives the solar gap against SMARD?

25_compare_solar_approaches found approach 1 (PECD official x MaStR-by-technology capacity) tracks SMARD reasonably well overall (corr=0.940, MAE=0.033) but with a small positive bias that grows over the backtest period (2018: 0.006, 2025: 0.026). This notebook checks two distinct candidate explanations, mirroring 22_analyse_bias_drivers’s wind investigation but adapted for what’s actually different about solar:

  • Curtailment, growing over time -- the same pattern found for wind, where the bias stepped up after 2022-2023 alongside real, reported increases in German curtailment. If solar shows the same CF-level and year-over-year shape, that’s evidence for the same explanation.

  • Behind-the-meter self-consumption -- specific to solar: MaStR’s pv_category shows ~44% of German solar capacity is self-consumption (with or without storage), which SMARD’s net grid-injected generation figure never sees (see ../markdown/index.md’s “behind-the-meter blind spot”). Since our modeled series is a gross capacity factor, periods/eras with a higher self-consumption capacity share should show a larger gap if this is a real contributor -- a check wind never needed, since wind has negligible self-consumption.

import matplotlib.pyplot as plt
import numpy as np
import pandas as pd

from pecdr.capacity_weighting import capacity_weighted_cf, hourly_capacity_by_zone, total_hourly_capacity
from pecdr.paths import ProjPaths

paths = ProjPaths()
paths.ensure_directories()

Rebuild approach 1 vs. SMARD, same as 25_compare_solar_approaches¶

solar_capacity_month = pd.read_parquet(paths.solar_capacity_by_nuts2_month_file)

pecd_solar_cf = pd.read_parquet(paths.pecd_solar_capacity_factors_file)
pecd_solar_cf.columns = [f"{tech}_{region}" for tech, region in pecd_solar_cf.columns]

tech_region_capacity = solar_capacity_month.copy()
tech_region_capacity["region_code"] = tech_region_capacity["pecd_technology"] + "_" + tech_region_capacity["nuts2_region"]
model_cf = capacity_weighted_cf(pecd_solar_cf, tech_region_capacity)

target_panel = pd.read_parquet(paths.target_panel_file)
total_region_capacity = solar_capacity_month.groupby(["nuts2_region", "month"])["capacity_mw"].sum().reset_index()
total_region_capacity = total_region_capacity.rename(columns={"nuts2_region": "region_code"})
total_capacity_hourly = total_hourly_capacity(total_region_capacity, target_panel.index)
smard_cf = target_panel["pv"] / total_capacity_hourly

comparison = pd.DataFrame({"model_cf": model_cf, "smard_cf": smard_cf}).dropna()
comparison["diff"] = comparison["model_cf"] - comparison["smard_cf"]

# Self-consumption capacity share, national, broadcast to hourly -- reuses
# `hourly_capacity_by_zone` with `pv_category` as the "zone" key, exactly
# as it's normally used for a spatial zone.
pv_category_month = pd.read_parquet(paths.solar_capacity_by_pv_category_month_file)
pv_category_hourly = hourly_capacity_by_zone(pv_category_month, comparison.index, zone_col="pv_category")
self_consumption_cols = [c for c in ["self_consumption_no_storage", "self_consumption_with_storage"] if c in pv_category_hourly.columns]
comparison["self_consumption_share"] = pv_category_hourly[self_consumption_cols].sum(axis=1) / pv_category_hourly.sum(axis=1)

print(f"Hours compared: {len(comparison):,}")
print(f"Bias: {comparison['diff'].mean():.4f}, MAE: {comparison['diff'].abs().mean():.4f}, corr: {comparison['model_cf'].corr(comparison['smard_cf']):.4f}")

Takeaways¶

The diurnal chart above was the real finding of this notebook, and it doesn’t look like it belongs in the same “curtailment” story as wind’s: testing a range of hour shifts between the model and SMARD series (not shown here, done as a one-off check) found that PECD’s solar CF product runs 1 hour ahead of true UTC -- shifting it back cuts MAE against SMARD roughly in half (0.033 -> 0.016) and correlation rises from 0.940 to 0.982, consistently across every year, not just on average. The same shift test on PECD’s wind product found no such improvement, so this isn’t a bug in how this project reads PECD’s files (pecdr.pecd_io handles both identically) -- it’s specific to PECD’s own solar product, plausibly inherited from ERA5’s solar-radiation fields being accumulated over the preceding hour while wind speed is instantaneous, a labeling convention PECD’s solar product doesn’t appear to correct for. Fixed at the source in pipeline/17_process_pecd_capacity_factors.py; every number in this notebook and in 25_compare_solar_approaches already reflects the correction.

With that artifact removed, what’s left is smaller and a genuinely different shape than wind’s monotonic curtailment pattern: bias is positive across most of the CF range but flips negative at the very highest CF bins (clear-sky summer middays) -- the opposite direction curtailment would push it. Not yet explained; a candidate worth checking before assuming it’s physical is whether the monthly capacity snapshot used for weighting lags Germany’s rapid recent solar build-out within a given month, understating capacity (and so overstating CF) precisely when a month’s true capacity was still rising toward its end.

The year-over-year growth in bias (2018: 0.006 -> 2025: 0.026) survives the timestamp fix unchanged, and self-consumption share tracks it closely too -- but self-consumption share has grown monotonically over the same period, so this notebook can’t separate “more curtailment over time” from “more self-consumption over time” from these two panels alone. Both remain plausible, real, solar-specific contributors to revisit once the per-plant physics replication (this workstream’s still-open Phase B) gives an independent way to cross-check.
