Comparing the two data sources

Chapter 1 covered SMARD’s monthly, TSO+DSO, ex-post counterfactual series; chapter 2 covered netztransparenz’s per-measure, TSO-issued, mostly technology-anonymous export. This notebook reconciles the two: how much do their totals actually agree, per technology and in aggregate, why they differ, and how far a statistical attribution can go in resolving the per-measure file’s missing technology labels.

import matplotlib.pyplot as plt
import numpy as np
import pandas as pd
from scipy.optimize import nnls

from pecdr.paths import ProjPaths
from pecdr.redispatch_measures import load_redispatch_measures

paths = ProjPaths()
paths.ensure_directories()

measures = load_redispatch_measures(paths.redispatch_measures_file)
reduction = measures.loc[measures["direction"] == "reduction"]
smard = pd.read_parquet(paths.redispatch_by_source_file)
smard_reduction = smard.loc[smard["direction"] == "reduction"]

overlap_start = max(reduction["month"].min(), smard_reduction["month"].min())
overlap_end = min(reduction["month"].max(), smard_reduction["month"].max())
print(f"Overlapping period used throughout: {overlap_start.date()} .. {overlap_end.date()}")

reduction_overlap = reduction.loc[reduction["month"].between(overlap_start, overlap_end)]
smard_overlap = smard_reduction.loc[smard_reduction["month"].between(overlap_start, overlap_end)]

Do the aggregate totals match?¶

Not evenly -- the gap is concentrated in one category, not spread across all of them.

Conventional plants match reasonably well (~93%); renewables have a real but moderate gap (~68%); the Sonstiges/Unbekannt catch-all -- mostly countertrading, per the previous chapter -- is the dominant driver of the overall shortfall, matching only ~13%. netztransparenz’s per-measure “Redispatch” export barely captures countertrading at all (its own Strombedingter Countertrade DE-DK1/DE-DK2/DE-NO2 reason codes are a tiny fraction of total volume), while SMARD folds all of it into the by-energy-source view (chapter 1).

Why the totals differ: three factors, not one¶

  1. Grid-level scope. SMARD’s renewable figure is TSO+DSO combined (chapter 1); this file is TSO-issued only.

  2. Measure-type scope. SMARD’s figure folds in countertrading and grid-reserve volume; this file is almost entirely Strombedingter/ Spannungsbedingter Redispatch (chapter 2).

  3. Settlement methodology. SMARD’s figure is a settled, ex-post counterfactual (“Ausfallarbeit”) that’s systematically larger than a simple instructed-power reading whenever conditions improved during a measure (chapter 1’s methodology section) -- this file’s own GESAMTE_ARBEIT_MWH is plausibly the latter, simpler quantity.

None of these were individually sufficient to fully explain the gap when checked in isolation earlier in this investigation -- it’s a combination.

Geo-information: both sources are limited, in different ways¶

SMARD’s monthly series has none at all -- purely a national total. This per-measure file has a coarse proxy only: the instructing TSO (ANWEISENDER_UENB, 4 zones), with the caveat that TenneT’s zone spans both the North Sea coast and Bavaria. Neither source has real coordinates or a finer administrative region field.

Attributing the ambiguous entities¶

Rather than allocating individual measures (tens of thousands of them, no natural prior to optimize against), the right unit is the entity -- each of the ~200 substation/cluster names is a physical grid connection point whose technology mix is very unlikely to change month to month.

Attempt 1: MaStR -- a clean dead end¶

MaStR models grid connection points as a first-class concept (netzanschlusspunkte/GridConnections, with human-readable name fields, linked to the actual generation units) -- checked by reading open_mastr’s ORM directly. In practice: getting this data required a fresh ~25-minute bulk download (5.77 million grid-connection rows, 6.68 million location rows), and it turned out to be a dead end, not just inconclusive. Both name fields are populated at individual household/plant level ("Egenbüttelweg 45, i.B. 05.07.2017, 7,99 kWp", or opaque internal IDs), not TSO-level substation/cluster names. Searching all 5.77 million rows for the actual place-name fragments behind the biggest ambiguous entities (Dörpen, Diele, Süderdonn, Heide West, Handewitt) returned zero matches; a Büttel search returned 21 rows, none of them the actual UW Büttel entity (all unrelated coincidences like Egenbüttelweg). MaStR conceptually supports this kind of join, but the TSOs’ own redispatch-cluster naming is evidently their own internal convention with no counterpart in MaStR’s registry.

Attempt 2: seasonal-fingerprint attribution¶

Wind and PV curtailment have close-to-opposite seasonal shapes. This builds a normalized reference shape for each from the cleanly-identified subsets, then fits each ambiguous entity’s own monthly series as a non-negative combination of the two via scipy.optimize.nnls -- a small, well-determined regression per entity (2 unknowns against however many months of its own history exist), not one large fit across all ~200 entities simultaneously (which would be underdetermined, given only ~50 months of aggregate constraints to pin down ~400 unknowns).

ambiguous = renewable_reduction.loc[renewable_reduction["tech"] == "ambiguous"]

wind_fingerprint = renewable_reduction.loc[renewable_reduction["tech"] == "offshore_wind"].groupby(renewable_reduction["month"].dt.month)["mwh"].sum()
pv_fingerprint = renewable_reduction.loc[renewable_reduction["tech"] == "pv"].groupby(renewable_reduction["month"].dt.month)["mwh"].sum()
wind_fingerprint = (wind_fingerprint / wind_fingerprint.sum()).reindex(range(1, 13), fill_value=0.0)
pv_fingerprint = (pv_fingerprint / pv_fingerprint.sum()).reindex(range(1, 13), fill_value=0.0)

entity_monthly = ambiguous.groupby(["entity", "month"])["mwh"].sum().reset_index()
entity_monthly["cal_month"] = entity_monthly["month"].dt.month

MIN_MONTHS_TO_FIT = 3
fitted_rows = []
for entity, grp in entity_monthly.groupby("entity"):
    y = grp["mwh"].to_numpy()
    design = np.column_stack([wind_fingerprint.loc[grp["cal_month"]].to_numpy(), pv_fingerprint.loc[grp["cal_month"]].to_numpy()])
    if len(y) < MIN_MONTHS_TO_FIT:
        fitted_rows.append(grp.assign(wind_mwh=np.nan, pv_mwh=np.nan))
        continue
    weights, _ = nnls(design, y)
    predicted_total = design[:, 0] * weights[0] + design[:, 1] * weights[1]
    wind_fraction = np.divide(design[:, 0] * weights[0], predicted_total, out=np.full_like(y, 0.5), where=predicted_total > 0)
    fitted_rows.append(grp.assign(wind_mwh=wind_fraction * y, pv_mwh=(1 - wind_fraction) * y))

fitted = pd.concat(fitted_rows)
resolved = fitted.dropna(subset=["wind_mwh"])
overall_wind_share = resolved["wind_mwh"].sum() / (resolved["wind_mwh"].sum() + resolved["pv_mwh"].sum())
fitted["wind_mwh"] = fitted["wind_mwh"].fillna(fitted["mwh"] * overall_wind_share)
fitted["pv_mwh"] = fitted["pv_mwh"].fillna(fitted["mwh"] * (1 - overall_wind_share))
print(f"Volume-weighted wind share among directly-fit entities: {overall_wind_share:.1%}")

entity_summary = (
    fitted.groupby("entity")
    .agg(n_months=("mwh", "size"), total_mwh=("mwh", "sum"), wind_mwh=("wind_mwh", "sum"), pv_mwh=("pv_mwh", "sum"))
    .assign(wind_share=lambda d: d["wind_mwh"] / d["total_mwh"])
    .sort_values("total_mwh", ascending=False)
)

The reconstructed series tracks SMARD’s shape reasonably (peaks and troughs align) but sits consistently below it -- the same ~32% aggregate renewables shortfall from the top of this notebook, not a new error introduced by the attribution. This makes the per-measure file (and this attribution) a better source for relative technology split and timing than for absolute monthly levels.

What’s still open¶

  • Understanding the residual gap even after accounting for grid-level, measure-type, and methodology differences.

  • A geographic cross-check: geocode each ambiguous entity’s place name and look up nearby installed wind/PV capacity directly from the MaStR technology tables (wind.parquet/solar.parquet, which do have longitude/latitude) as an independent check on the seasonal-fingerprint attribution above -- not yet done.

  • See the next chapter: real curtailment turns out not to fully explain the raw potential-vs-observed gap -- worth checking whether negative day-ahead prices, which can also drive voluntary curtailment outside of redispatch, account for the rest.
