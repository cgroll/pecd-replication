Estimating curtailment: calibrated on wind, applied to PV

Fits equations 9-10a from book/markdown/curtailment_system_equations.md. Wind’s own gap (P_i(t) - G_i(t)) has no behind-the-meter term to separate out -- it’s L_repair + L_price + L_congestion + ε directly, a clean signal for how curtailment responds to system-wide oversupply. That relationship, fit on wind, is then applied to PV’s own oversupply hours; what’s left over in PV’s gap after subtracting the predicted curtailment is an estimate of PV’s self-consumption plus its own repair losses and model error.

Curtailment is expressed as a rate relative to each technology’s own potential (Gap_i(t) / P_i(t)), not an absolute MW level, before transferring the wind-fitted relationship to PV -- wind and PV have very different capacity scales, so only a fraction of potential lost is meaningfully comparable across technologies experiencing the same system-wide oversupply conditions.

The oversupply proxy used here is the potential-based one (equation 9: P_total(t) / D_true_hat(t)), not the observed one from notebooks 22/36 -- the observed version is built from already-curtailed values, so it understates true oversupply exactly when curtailment is largest.

import matplotlib.pyplot as plt
import numpy as np
import pandas as pd
import statsmodels.formula.api as smf

from pecdr.domain import FULL_YEAR_BACKTEST_YEARS
from pecdr.paths import ProjPaths
from pecdr.residual_load import AGGREGATE_DEMAND_FORMULA, curtailment_rate, fit_curtailment_curve, predict_curtailment_mw

paths = ProjPaths()
paths.ensure_directories()

PERIOD_LABEL = f"{FULL_YEAR_BACKTEST_YEARS[0]}-{FULL_YEAR_BACKTEST_YEARS[-1]}"

Rebuild gross demand and the potential-based oversupply proxy¶

inputs = pd.read_parquet(paths.residual_load_inputs_file)
target_panel = pd.read_parquet(paths.target_panel_file).reindex(inputs.index)

# Aggregate specification (equation 7, not the uninstrumentable 7a split -- see notebook 38)
demand_model = smf.ols(AGGREGATE_DEMAND_FORMULA, data=inputs).fit()
d_true_hat = demand_model.predict(inputs.assign(P_pv_mw=0.0))

p_total = inputs["P_wind_on_mw"] + inputs["P_wind_off_mw"] + inputs["P_pv_mw"]
oversupply_proxy = p_total / d_true_hat
print(f"Oversupply proxy: mean {oversupply_proxy.mean():.3f}, 99th pct {oversupply_proxy.quantile(0.99):.3f}")

bins = np.linspace(0, oversupply_proxy.quantile(0.995), 21)
bin_mid = [interval.mid for interval in pd.IntervalIndex(pd.cut(oversupply_proxy, bins).cat.categories)]

Wind’s own gap: clean, BTM-free curtailment signal¶

Expressed as a rate (Gap / P), restricted to hours with at least 5% of each technology’s own peak potential -- below that, the ratio is noisy and not physically meaningful (curtailing 2 MW out of a possible 3 MW means something very different from curtailing 2000 out of 3000).

min_potential_on = 0.05 * inputs["P_wind_on_mw"].max()
min_potential_off = 0.05 * inputs["P_wind_off_mw"].max()

rate_wind_on = curtailment_rate(inputs["P_wind_on_mw"], target_panel["wind_onshore"], min_potential_on)
rate_wind_off = curtailment_rate(inputs["P_wind_off_mw"], target_panel["wind_offshore"], min_potential_off)

Robustness check: do onshore and offshore show the same curtailment-vs-oversupply shape?¶

Both are structurally BTM-free, so if their curtailment response to the same system-wide oversupply proxy diverges sharply, the “one shared curve” assumption used below is too coarse (e.g. differing grid-connection constraints per technology).

rate_on_by_bin = fit_curtailment_curve(rate_wind_on, oversupply_proxy, bins)
rate_off_by_bin = fit_curtailment_curve(rate_wind_off, oversupply_proxy, bins)

fig, ax = plt.subplots(figsize=(9, 5))

The pooled wind curtailment curve, and its transfer to PV¶

gap_pv = inputs["P_pv_mw"] - target_panel["pv"]

p_wind_total = inputs["P_wind_on_mw"].where(inputs["P_wind_on_mw"] > min_potential_on, 0) + inputs["P_wind_off_mw"].where(
    inputs["P_wind_off_mw"] > min_potential_off, 0
)
gap_wind_total = (inputs["P_wind_on_mw"] - target_panel["wind_onshore"]).where(inputs["P_wind_on_mw"] > min_potential_on, 0) + (
    inputs["P_wind_off_mw"] - target_panel["wind_offshore"]
).where(inputs["P_wind_off_mw"] > min_potential_off, 0)
rate_wind_pooled = (gap_wind_total / p_wind_total).where(p_wind_total > 0)

rate_pooled_by_bin = fit_curtailment_curve(rate_wind_pooled, oversupply_proxy, bins)
predicted_curtailment_pv = predict_curtailment_mw(rate_pooled_by_bin, oversupply_proxy, inputs["P_pv_mw"])
residual_pv = gap_pv - predicted_curtailment_pv

print(f"PV raw gap: mean {gap_pv.mean():.0f} MW")
print(f"PV predicted curtailment (wind-calibrated): mean {predicted_curtailment_pv.mean():.0f} MW")
print(f"PV residual (BTM + repair + model error): mean {residual_pv.mean():.0f} MW")

Takeaways¶

  • Onshore and offshore agree reasonably well from oversupply~0.6 upward -- the region that matters most for transferring the curve to PV, since PV’s own oversupply hours (daylight, when PV itself contributes to the numerator) skew toward this range. Below that, offshore’s rate goes sharply negative (as low as -0.7) while onshore stays mildly positive -- a real divergence, not smoothed over here, most plausibly a residual imperfection in the offshore replication at low wind speeds (this project’s own offshore chain is the newer, less independently cross-checked of the two) rather than evidence the shared-curve assumption is wrong where it’s actually used.

  • The wind-calibrated curve explains most of PV’s raw gap: of the ~2177 MW average gap, ~1605 MW (74%) is predicted curtailment, leaving a ~519 MW residual for self-consumption + repair + model error -- curtailment, not self-consumption, is the larger piece of PV’s own gap, which wasn’t obvious going in.

  • The residual correlates with the self-consumption-registered capacity share at 0.643 -- supportive, but both series simply trend upward over 2019-2025, so part of this is two trending series moving together rather than tight month-to-month co-movement. Worth a follow-up detrended check (year-over-year differences instead of levels) before leaning on this number heavily.
