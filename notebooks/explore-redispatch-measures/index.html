Data source: netztransparenz’s per-measure Redispatch export

The previous chapter covered SMARD’s monthly, TSO+DSO, ex-post counterfactual series. netztransparenz.de separately publishes a live, per-measure export -- real start/end timestamps, per-plant/cluster names, a coarse energy-type flag -- with different tradeoffs. This notebook describes it on its own terms; the comparison chapter reconciles the two.

import matplotlib.pyplot as plt
import pandas as pd

from pecdr.paths import ProjPaths
from pecdr.redispatch_measures import load_redispatch_measures

paths = ProjPaths()
paths.ensure_directories()

measures = load_redispatch_measures(paths.redispatch_measures_file)
reduction = measures.loc[measures["direction"] == "reduction"]
renewable_reduction = reduction.loc[reduction["primary_energy_type"] == "Erneuerbar"]
colors = plt.rcParams["axes.prop_cycle"].by_key()["color"]

Attributes of this data source¶

AttributeValue
Grid levelEvery measure’s ANWEISENDER_UENB (instructing party) is one of the four German TSOs -- checked directly, never a DSO name. This confirms TSO-issued, but not necessarily TSO-connected-only: a TSO can instruct redispatch for a distribution-connected plant too, so this isn’t a clean TSO-vs-DSO split the way SMARD’s own s-nepm_re_eb series is.
FrequencyPer-measure -- real start/end timestamps (often sub-hourly), not a monthly aggregate.
Source typeCoarse: Konventionell / Erneuerbar / Sonstiges only. Within Erneuerbar, the plant/cluster name reveals the specific technology for offshore wind 100% of the time, but only ~1% of onshore wind’s and ~4% of PV’s true volume -- most of both sit under anonymous substation/cluster codes (see “ambiguous” below).
MethodologyLikely ex-post but mechanical -- GESAMTE_ARBEIT_MWH reads like an immediate figure (instructed power x duration), not the settled, weather-informed counterfactual SMARD’s monthly figure represents. This is an inference from the field’s role in a live operational export, not a confirmed specification.
Location dataA coarse proxy only: ANWEISENDER_UENB/ANFORDERNDER_UENB (instructing/requesting TSO, 4 zones) -- no coordinates. TenneT’s zone spans both the North Sea coast and Bavaria, so it doesn’t map cleanly to “region.”

Relevant facts about this data¶

A naming-convention change silently affected technology classification partway through the file. Four of TenneT’s North Sea offshore grid-connection substations (Büttel, Diele, Dörpen-West, Emden-Ost) were reported as "OWP UW ..." through July 2025, then as plain "UW ..." from August 2025 onward -- the same physical, offshore-only substations, just relabeled. A name-substring classifier has no way to know that on its own; pecdr/redispatch_measures.py handles it with an explicit RENAMED_OFFSHORE_SUBSTATIONS list, found by noticing an odd shape in an early version of the chart below (offshore appearing to collapse for several months, exactly mirrored by a spike in the “ambiguous” bucket) -- a reminder that classification keyed on scraped naming conventions needs to be re-checked periodically, not assumed stable.

def classify_summary(df: pd.DataFrame) -> pd.Series:
    return df.groupby("tech")["mwh"].sum().sort_values(ascending=False)

Takeaways¶

  • This is a TSO-issued, per-measure, ex-post-but-mechanical figure with a much finer time resolution than SMARD’s monthly series, but a much coarser technology label for anything except offshore wind.

  • Offshore wind is fully name-identifiable; onshore wind and PV are overwhelmingly hidden behind anonymous substation/cluster codes.

  • A real naming-convention change mid-file is a concrete reminder that scraped classification needs periodic re-validation, not a one-time fit.
