Fitting optimal PEOF-zone capacity weights: is the bias just wrong fleet numbers?

34_compare_wind_offshore_approaches found “PECD official x MaStR” biased +0.060 CF against SMARD, using our own mastr_capacity_by_peof_month panel as the capacity weights on both sides of that comparison. That panel is not one of PECD’s outputs -- it’s built here from MaStR’s commissioning_date/final_shutdown_date, so if it’s wrong (e.g. commissioning dates front-run real grid-connection ramp-up, or units are assigned to the wrong PEOF zone), that alone could manufacture the bias without any real curtailment involved.

This asks a sharper question: holding PECD’s own zone capacity-factor shapes fixed, what’s the best possible per-zone capacity vector, and how much of the SMARD gap does it close? If the optimal vector still can’t explain SMARD well, wrong fleet numbers are ruled out as the (sole) explanation.

Method¶

Solve SMARD_actual_MW(t) ~ sum_z w_z(t) * PECD_CF_z(t) for the per-zone capacity weights w_z(t), via ordinary least squares with two physical constraints: w_z(t) >= 0, and w_z monotonically non-decreasing in t (no German offshore capacity was decommissioned in 2019-2025, only added). The monotonicity constraint turns into a plain non-negativity constraint via a reparametrization: instead of estimating w_z(t) directly, estimate non-negative monthly increments d_z[m] >= 0 (capacity newly delivering in zone z, month m -- the first month’s increment absorbs whatever was already installed before the fit window starts), so w_z(t) = sum_{k <= month(t)} d_z[k] is automatically monotonic. Substituting back in, the model is linear again in d, solved with plain NNLS (scipy.optimize.nnls) on a transformed design matrix: column (z, k) at hour t is PECD_CF_z(t) if month(t) >= k, else 0.

Two things this can’t cleanly separate¶

  • Only 3 of PECD’s 6 PEOF zones have any data at all. DE013_OFF/DE014_OFF/DE015_OFF are 100% NaN in PECD’s own product across the entire 2015-2025 file -- PECD apparently never modeled them. DE013_OFF still carries real MaStR capacity (up to ~300 MW) -- a separate, genuine data-quality issue: the previous notebook’s “PECD official x MaStR” number silently dilutes its capacity-weighted denominator with this dead-weight capacity (MaStR capacity that contributes zero numerator, since its CF is NaN and pandas’ default skipna sum just drops it). Only the 3 zones PECD actually models (DE011_OFF, DE012_OFF, DE02_OFF) can be fit or fairly compared here.

  • Those 3 zones sit close together and see highly correlated wind, so the design matrix is poorly conditioned for separating individual zone weights -- capacity can trade between DE011_OFF and DE012_OFF in the fit without much cost in fit quality. The national total (summed across zones) is the trustworthy readout; per-zone trajectories below are shown but shouldn’t be over-interpreted individually.

Build the monotonic-increment design matrix and solve NNLS¶

zones = list(cf.columns)
row_period = cf.index.to_period("M")
months = row_period.unique().sort_values()
month_idx = months.get_indexer(row_period)
n_zones, n_months = len(zones), len(months)

# mask[t, k] = True if hour t's month is on or after month k -- shared
# across zones, since it only depends on which month each hour falls in.
month_mask = np.arange(n_months)[None, :] <= month_idx[:, None]
design_matrix = np.hstack([cf[z].to_numpy()[:, None] * month_mask for z in zones])

fitted_increments, residual_norm = nnls(design_matrix, smard_mw.to_numpy(), maxiter=10_000)
fitted_capacity_by_month = fitted_increments.reshape(n_zones, n_months).cumsum(axis=1)
fitted_capacity = pd.DataFrame(fitted_capacity_by_month.T, index=months, columns=zones)
print(f"Non-zero monthly increments: {(fitted_increments > 1.0).sum()} / {len(fitted_increments)}")

Does the optimal capacity vector actually fit SMARD better?¶

Compares the fitted-optimal reconstruction against the MaStR-weighted reconstruction, both restricted to the same 3 PECD-modeled zones (so this isolates the effect of reweighting capacity, not the separate dead-weight-capacity issue from DE013_OFF) -- both in MW directly against SMARD’s actual generation.

predicted_fitted_mw = design_matrix @ fitted_increments

mastr_hourly = hourly_capacity_by_zone(mastr_peof_month, cf.index, zone_col="region_code").reindex(columns=zones).fillna(0)
predicted_mastr_mw = (cf.to_numpy() * mastr_hourly.to_numpy()).sum(axis=1)

Reading the result¶

The optimal capacity vector drives bias to roughly zero (vs. a clear positive bias from the MaStR-derived weights) -- a real chunk of the previously-observed bias is attributable to our own capacity accounting, not to PECD’s modeling or to curtailment. But correlation barely moves between the two -- reweighting capacity fixes the level, not the shape. Since the fitted vector is, by construction, the best any monotonic per-zone capacity story can possibly do, the remaining correlation gap can’t be closed by better fleet data -- it needs something dynamic that a static (or monotonically growing) capacity vector structurally can’t represent: curtailment, outages, or another time-varying effect neither this fit nor PECD’s own product attempts to model.
